# R9 development protocol: matched source contrast

Status: **development protocol, not a scored result or Gate 2 admission**.
This record fixes the evidence required before a new B/C source lineage can
enter a reader or researcher experiment. The R8 PEP and PostgreSQL worlds
remain unqualified: a fixed, source-free action map passed both sessions even
when their source documents were withheld. Their action and receipt tests are
construction witnesses, not evidence that a reader needs the long source.

## Claim and unit

The first claim is narrow: changing the decisive source rule while holding
the constructed project state fixed changes the legal later action. One
upstream source/project lineage is the independent unit. Version pairs,
position changes, environment mutations, and repeated model draws within
that lineage are paired measurements, not additional independent parents.
Two qualified lineages are a sanity floor for a transfer pilot, not a sample
size or power justification for a population claim.

The matched diagnostic pair must have byte-identical policy-visible
non-source `StageView` fields, document metadata, constructed documents,
session boundary, carry contract, tool interface, and predecision tool
responses. Only the separately pinned, source-bearing text may differ.
The evaluator-only legal later action must flip. A fixed source-free policy
must be run unchanged on both members; if it passes both, or if an instance
name, prompt, receipt, feedback, API name, or metadata reveals the version's
answer, reject the contrast. Test source-full reference completion and
independent earlier-action and current-receipt interventions. Treat an
edited source as a separately hashed constructed counterfactual, never as
an authentic upstream revision. Real revision pairs must retain exact
upstream bytes and immutable checkout identities.

This paired impossibility test is a **structural** source-dependence witness:
a deterministic source-free policy cannot choose both opposite answers from
identical non-source observations. It does not establish that a fixed model
actually reads the long source, uses early evidence, or benefits from policy
improvement. A task with a source-free successful strategy or a saturated
fixed baseline remains development material.

## Gates in order

| Gate | Required evidence | Decision |
| --- | --- | --- |
| Identity | Registry dry run before acquisition; detached clean immutable source checkouts; selected file, blob, span and license hashes; world, policy, tokenizer, profile and budget hashes | Reject drift before any run |
| Offline causality | Matched source-swap pair, unchanged source-free fixed policy, full-source reference, earlier-action and current-receipt interventions, forged/failed/stale receipt rejection | Reject leak or missing action dependency |
| Exact request geometry | Capture actual final worker request messages; render with the pinned tokenizer and chat template including system role and generation wrapper; record prompt token count, decisive span token interval, query interval and evidence-to-query distance per call | Do not use whitespace or source-only length as final-chat length |
| Fixed-reader development | Frozen worker identity/decoding/budget/order; two reader families; full source, source-free, decisive removal/swap, irrelevant equal-length change, early/middle/late placements; inspect traces and named errors | Reject non-solvability, source-free success, saturation, or position collapse |
| Researcher pretest | Trusted jailed broker, prospective attempts, audited changed snapshots, metered worker exercise, provider-reported target and auxiliary usage | No paid pretest until jail and identity gates pass |
| Sealed evaluation | New independent parents, frozen task/profile/manifest, no inspected item feedback; register parent-level sample size, paired effect and clustered interval first | No transfer or improvement claim from development variants |

For the fixed-reader screen, retain the contract's complete-evidence
solvability, no-policy-at-or-above-0.90 and top-two policy disagreement of at
least 20% diagnostics. Report whole-project B/C completion as the primary
outcome, and decision legality, evidence/receipt provenance, retries, errors,
and costs separately. A reset alone does not prove carry is necessary when
the policy may reread source or query the persistent sandbox.

The prospective researcher update-rate denominator is **all planned
attempts**, including invalid outputs, API errors and timeouts. Report both
valid-submitted/all-planned and audited-and-exercised/all-planned, with task
success separate. Use provider token usage for real worker and researcher
calls; report unknown usage as unknown rather than substituting a local word
count. Distinguish improvement cost from deployment cost and compute a
break-even horizon only after a successful paired evaluation.

## Runtime admission

The current host is not admitted for live model-authored policy execution.
`policy_jail.py` correctly refuses the UID-1000-owned `/usr/bin` and
`/usr/lib` ancestors before launching host programs; the root overlay is
writable and has no separate read-only `/usr` mount. Copying only
`setpriv` or `unshare` would still traverse replaceable dynamic loaders and
libraries. Keep the gate closed until the unchanged jail passes unskipped
adverse and paired B/C tests on a clean host with root-owned immutable
runtime paths, or on an independently attested complete trusted runtime
bundle. Do not relax the ancestor checks to obtain a pilot result.

The project has a root-readable `ops/env/local-env.sh` in the adjacent
environment repository for Siflow credentials; no secret value belongs in
manifests or logs. Credential availability does not waive task, runtime or
model-identity gates.

## Related design references

[RULER](https://arxiv.org/abs/2404.06654) motivates length and multi-step
position tests; [LongBench v2](https://aclanthology.org/2025.acl-long.183/)
motivates real-document reasoning and answer validation;
[LongMemEval](https://arxiv.org/abs/2410.10813) motivates multi-session
updates and abstention. [GEPA](https://arxiv.org/abs/2507.19457) motivates
an equal-cost reflective optimizer control once matched search controls are
implemented. These are design references, not directly comparable scores.
The existing [benchmark contract](../benchmark-contract-v2.md) defers
non-agent search controls, so R9 cannot claim learning beyond search.
