Status: **design queue, not a frozen panel or launch authorization**. R11
PostgreSQL and R12 OpenTelemetry each validate one two-version development
question under one model-driven policy. Their variants, source swaps,
positions, and repeated worker calls do not create additional independent
tasks or parents. The benchmark contract clusters at world/trajectory level;
the qualified independent-parent count remains zero.

## Task-card intake before any new provider block

The first possible 16-trajectory panel would require **eight distinct,
source-adjudicated project decisions**, each instantiated against two pinned
revisions. Four per lineage is a working capacity target, not a finding that
the existing material supports four valid paired tasks. A reviewer must
freeze each card's exact request, source evidence span, legal action in both
revisions, receipt/action chain, source-free alternative, and complete-project
success condition before measuring a reader. A paraphrase or position shift
of one decision remains the same card.

## Conditional experiment package

Once all cards and their private oracles are frozen, run the same complete
two-session outcomes under two pre-registered fixed policies on the primary
reader and policy A on a second reader family. Policy A can retain a compact
answer catalog; policy B should retain
source-cited evidence with a different information preservation mechanism.
Both receive equal tool, call, token, carry, receipt, and action budgets.
Freeze a model-invoked source-free arm with answer-free material; the R11/R12
withheld arms are guard checks that never call the worker. For four selected
sentinel cards, add target-rule transplant or all-other-cue neutralization,
equal rendered-token irrelevant edits, and early/middle/late placements using
the same source bytes and neutral filler. Validate final-chat positions with
the pinned tokenizer. Run controls only after the complete-source cards pass
their solvability preflight. Any edited source is labelled constructed and
hashed separately from authentic upstream revisions.

| Stage | Conditional trajectories | Question answered | Stop before next stage if |
| --- | ---: | --- | --- |
| Complete source: 16 cards × 2 policies on primary reader, plus 16 on second reader | 48 | solvability, saturation, strategy disagreement, cross-reader coverage | identity, canary, source oracle, model echo, usage or geometry fails |
| Model-invoked source-free: two opposite-action pairs × 2 readers | 8 | answer-free prior-knowledge shortcut | control is not answer-free or model is not actually called |
| Target-rule retained/removed: four sentinels × 2 variants × 2 readers | 16 | rule contribution after other cues are controlled | material edit changes unrelated semantics |
| Equal-token irrelevant edit: four sentinels × 2 readers | 8 | length/interference sensitivity | rendered token envelope differs |
| Placement: four sentinels × 3 positions × 2 readers | 24 | early/middle/late robustness | evidence position or source bytes drift |

This package has a **conditional maximum of 104 trajectories and 208 task
worker attempts** at two calls each, plus separately counted canaries. It is
an upper planning envelope, not permission to spend that budget. Before any
API call, freeze exact 16 task cards, models and revisions, per-call output
caps, local worst-case input envelope, total provider-token caps, order,
random seeds, pre/post canaries, and stop rules. A proposed 2,000,000 input /
55,000 output token cap requires explicit local worst-case and provider-price
review; it is not a usage prediction. Stop early on full-source
non-solvability, source leakage, template mismatch, missing usage or wrong
model echo. A `≥0.90` score on a pre-registered development policy stops
further paid difficulty controls and records a saturation diagnostic; it does
not retroactively erase a strong method result. On a 16-card screen, 15/16 or 16/16
triggers that diagnostic; at least 4/16 paired actions must differ
for the `≥20%` top-two disagreement diagnostic. Report both metrics by
lineage as well as in aggregate.

The task evidence table needs one row per card × source revision × model ×
policy × intervention, with lineage, card ID, material and source hashes,
position stratum, both-session completion, action legality, receipt
provenance, carry bytes, failure reason and cost. A separate call ledger needs
request/profile/policy/tokenizer hashes, evidence/query token intervals,
attempt index, model echo, finish reason, provider input/output or unknown
usage, and latency. Use paired comparisons and world/trajectory clustering;
do not count version variants, interventions, or worker calls as independent
parents. The inspected development panel cannot later be an unseen gate, and
an unversioned Siflow profile cannot support a T2 statistical claim.
