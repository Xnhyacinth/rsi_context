## Counting unification

"24/24" = 16 visible + 8 gate instances, one run each, one final-state
check per instance. It is item-level counting, not stage checks or worlds.
The n=16 development panel uses **one shared template family
(research-v1)** over PopQA rows — 24 instances, but one template and one
corpus slice; they are NOT 24 independent task worlds. This weakens any
statistical reading and is recorded as a design limitation (independent
worlds are the review's step-4 deliverable).

## Where the answers entered, were retained, and were read out

Verified against the artifacts (not inferred):

1. **Entry**: the stateful hook (experience and DS arms) writes each
   act_verify stage's extracted answer into participant state
   (`notes.append({"stage": ..., "answer": ...})`,
   scripts/pilot_cell.py:_stateful_pack_hook). Fixed writes a constant `{}`.
2. **Retention**: SessionStateStore transcripts show it — fixed arm's
   state digest is constant (`44136f…` = sha256 of `{}`); experience arm's
   write sizes grow monotonically (58→100→144→193→248→301… bytes).
3. **Read-out**: the stateful hook prepends "Working notes so far:" (the
   accumulated notes, including prior answers) to the READER prompt for
   every subsequent stage/instance. Fixed's prompt has no such preamble.

**Critical fact — the state shortcut is NOT the main story.** The gate
session starts with byte-empty state (verified: gate write sizes restart
at 69→121→171 bytes; gate/visible item overlap = ∅), yet the experience
arm scored 8/8 on gate with empty initial state. So the visible-stream
answer carry explains at most within-visible convenience, not the 24/24.

## What actually produced 24/24 vs 0/24: a prompt-shape channel difference

The two arms differ in the READER PROMPT, not only in state:

- fixed hook: `Question:
{q}

Evidence:
{docs}` (no preamble).
- stateful hook: `Working notes so far:
(none)

{q}

Evidence:
{docs}` (preamble always present, even with empty notes).

Reader-input digests differ between arms accordingly. The fixed arm's 24
failures are 13 INSUFFICIENT + 5 empty + 6 wrong — reader-channel
behaviors under the bare prompt shape. The experience/DS arms' 24/24 is
the same reader under a slightly different prompt shape.

**Conclusion: the panel primarily measured a prompt-formatting channel
difference, not memory ability and not task difficulty.** This is the
review's "channel parity" failure, confirmed and dominant.

## The DS researcher's round: not wired back (0% disagreement explained)

The DS improvement round ran and produced a rewritten `strategy.py`
(archived under artifacts/pilot-cell/agent-workspace/agent/). But the
pilot script does NOT feed that file back into the runtime hook — the
ds-researcher arm's gate run uses the same `_stateful_pack_hook` as the
experience arm. The two arms are therefore runtime-identical by
construction; their 0% disagreement is an artifact of wiring, not a
finding. (Their recorded reader inputs are literally identical.)

## Three-case classification of the state carry (per the review)

| Case | Verdict for this panel |
| --- | --- |
| (a) legitimate observation-derived facts later needed | the notes' answer strings derive from legal in-session reader outputs — **legitimate memory content** if items recurred; here items do NOT recur (gate overlap ∅), so the carry mostly adds prompt noise |
| (b) answer caching on repeated items | **not present across splits** (gate items disjoint); would only matter within-visible |
| (c) reading hidden labels / has_answer / future material | **not present**: state content came only from the hook's own reader calls; the leak probe verified visible-gold canary tokens absent from gate state (16 entries scanned, clean) |

So the earlier "state shortcut saturation" diagnosis was **wrong in
emphasis**: no leakage, no cross-split caching; the dominant confound is
the prompt-shape channel difference plus the unwired DS output. The
family-revision item "forbid per-item answers in state" is therefore
**withdrawn** (per the review: it would penalize legitimate memory); the
correct fixes are channel parity and honest arm wiring.

## Where fixed lost parity, precisely

- The fixed arm has no note-taking surface at all (hook writes `{}`), so
  it cannot express the working-notes behavior the family's stage prompts
  ask for ("Build your working notes; they are your only carry-forward").
  The task text prescribes a capability the fixed arm structurally lacks —
  that is a comparison-design error (fixed ≠ "no improvement", it is
  "no memory"), conflating the review's "not updating" vs "not
  remembering" distinction.
- The reader (Qwen reasoning mode) is format-sensitive: the bare shape
  yields INSUFFICIENT/empty at 2048 budget; the preamble shape yields
  clean extractions. Both arms share ONE parser, so parser bugs are
  excluded; the difference is prompt shape — an agent-side interface
  strategy that the family currently bakes into the arm rather than the
  task.

## Channel-parity diagnostic result (run after the first draft of this report)

The dedicated diagnostic (scripts/channel_parity_diagnostic.py, n=8, gold
evidence only, three prompt shapes: bare / empty-notes preamble /
real-method-note) **rejects the channel-sensitivity hypothesis**:
A_bare = B_preamble = C_notes = 0.5. The prompt-shape difference does NOT
move the hit rate.

What the diagnostic shows instead, per item:

- `4402885` ("In what country is Wilcza Jama…?", expected Poland): the
  gold retrieval block is about a DIFFERENT entity ("Wilcza Góra") — the
  reader's INSUFFICIENT is arguably the correct behavior for the supplied
  evidence; the item label is not supported by its gold passage. **Label
  defect.**
- `1652383` ("What genre is Holiday?", expected "punk rock"): gold says
  the covering band defines its sound as "power pop, punk, punk pop" — the
  reader extracts that phrase verbatim; "punk rock" is a KILT-side
  normalization not present in the evidence. **Label/evidence mismatch
  (normalization gap).**
- `3006731` (expected "horror film"): gold says "comedy horror film"; the
  reader answers "comedy horror" — substring in neither direction. Same
  normalization-gap class.

So the panel's real difficulty structure is dominated by **answer-label
normalization mismatch** (KILT aliases vs evidence phrasing) plus some
**gold-retrieval defects**, and the fixed arm's 0/24 arose from these
items failing under a slightly harsher presentation, while the stateful
arm's within-run notes happened to include prior extracted phrasings that
sometimes matched the expected aliases (e.g. repeating "poet" once
extracted). The 24/24-vs-0/24 gap is then explained jointly by (i) item
label defects interacting with (ii) note-recycling of previously
extracted phrases — a mild form of case (b) from the review's table
(answer caching), **within** the visible stream and for gate items
through nothing (gate passed 8/8 with empty state because gate items'
gold passages happened to be the cleaner ones — verified: gate failure
taxonomy in the fixed arm is the same INSUFFICIENT/normalization classes
but on different, apparently cleaner items).

This REORDERS the root-cause ranking (below) and adds a family-level
fix: the answer-matching function must be alias-aware (PopQA
`possible_answers` lists aliases: 'Poland'/'POL'/'Republic of
Poland'/'Polska') — the material constructor currently pins
`possible_answers[0]` only. A substring/alias hit function over the full
alias list is the correct scorer, and gold-retrieval sanity (does the
gold passage actually entail the label?) must become an item-construction
gate.

## Root causes, ranked (revised after the diagnostic)

1. **Item label defects** (gold-retrieval mismatches + single-alias
   pinning with strict substring matching) — dominant cause of the
   difficulty structure; affects all arms.
2. **Within-run note recycling of extracted phrases** — the mild
   answer-caching channel (case b), within-visible only; explains the
   visible 16/16 vs bare-channel behavior on alias-clean items.
3. **DS improvement output not wired back** — invalidates the
   researcher-vs-experience comparison (0% disagreement is wiring).
4. **Task prescribes a capability the fixed arm lacks** (notes) —
   fixed-arm design conflates no-update with no-memory.
5. **One template, one corpus slice** — 24 instances are not independent
   worlds; panel statistics are screens at best.
6. ~~Channel asymmetry~~ — **rejected by the diagnostic** (rates equal
   across prompt shapes).
7. **State carry of in-session answers**: legitimate content per se; the
   "forbid per-item answers" revision remains withdrawn.

## Consequences for the next steps (feeding the review's step 2-3)

- Step 2 (state/branch contract): keep "frozen learning snapshot +
  independent evaluation branches" semantics; do NOT add
  method-experience-only; define fixed arm as "strategy frozen, memory
  fully operational" (the review's fixed-policy + working-state arm).
- Step 3 (diagnostics): channel equivalence is now VERIFIED (the
  diagnostic is step 3's second bullet, done); next probes in order —
  no-history vs history, fact-swap / evidence-missing /
  irrelevant-perturbation — on alias-scored, gold-sane items.
- **Item-construction gates added**: (i) alias-aware scoring over the
  full `possible_answers` list; (ii) gold-passage entailment sanity
  (does the gold text actually support the label?) as a build-time
  check; (iii) no single-alias pinning.
- The panel record stands as a **quality-control artifact**: it stopped
  an invalid comparison from being reported as a result, and its
  diagnosis corrected THREE of our own misreadings (shortcut emphasis,
  DS wiring, and the channel hypothesis that the diagnostic then
  rejected). It is development material, not a gate for unseen data.
