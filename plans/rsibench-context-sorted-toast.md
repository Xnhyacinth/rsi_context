## 一、目标（normative question，v2）

> **在固定模型服务、信息权限与资源约束下，不同自我改进方法能否通过连续任务经历，改善 Agent 的信息获取—上下文组织—记忆维护—规划执行—验证恢复策略？这些改善能否在未见任务流中保留与迁移？长期净收益（C_improve + N·C_deploy）如何？收益分别来自经验内容、策略更新还是额外计算？**

**项目类型**：Benchmark + 分析性研究。执行框架（runner/隔离/核算）是配套基础设施，不是贡献声明。
**判定测试**：把我们自己的默认改进算法删掉，让 Recuris 式记忆演化、MGM 式代码修改、AutoMem 式架构搜索、固定策略来参评——论文价值仍成立。

## 二、动机（三个机制假设，非既得结论）

1. **局部改善 ≠ 长期能力**：压缩省成本可能丢失后续才用的例外；记忆积累可能引入过期信息；委派扩大搜索但丢失出处；修复当前任务的技能可能被错误套用。改善一环不保证链条变好。
2. **"本次任务更好" ≠ "系统以后更会工作"**：可能只是多读/多调/多试/存了事实。须区分同一环境保持有效状态 vs 把工作方式迁移到新环境。
3. **长期净收益才是使用方关心的问题**：整理记忆/更新技能/重写 harness 何时优于固定系统+更多推理预算？何时更新会破坏已有能力？

## 三、价值贡献（只写三项）

1. **任务体系（最重要）**：耦合任务生命周期——长文档证据 + 跨会话状态 + 行动依赖，早期信息处理选择改变后续可用信息与行动质量，错误延迟暴露。相对近邻必须能回答它们不便回答的问题（见 §四对照表）。
2. **开放改进过程评测**：基准规定任务、反馈、信息权限、资源与结果定义；参评方法自带改进机制（记忆演化/代码编辑/架构搜索/不更新）。提供裁判与任务，不规定选手内部战术。
3. **系统性结论**：哪类经历带来可迁移改善、哪些局部收益随跨度消失、何时持续更新优于固定策略、哪些更新破坏旧能力、结论如何随模型与资源变化。**由结果产生，不预写。**

## 五、设计

### 5.1 提交对象（开放的参赛者面）

S = (初始 Agent 代码, 可保留状态规约, 改进过程代码, 模型服务配置)。不要求改 Python 才算改善（技能文本/配置/检索库/工作流皆可）。冻结的是被测系统**之外**的评价与管理层：隐藏评价、权限边界、任务时间顺序、资源核算、审计记录、结果定义。区分"外部强 researcher 辅助目标 Agent"与"同模型自我改进"，分开报告。

### 5.2 任务生命周期（核心新建）

三层结构：任务内部长程工作（理解/记忆/行动） + 多项目间持续改善（经验/策略/迁移）。首族四场景（评审 §五）：持续研究与证据综合、长期协作与事务执行、多阶段项目工作、自适应探索与委派。**种子实例**：评审的采购-部署例子（读资料定方案 → 新约束注入 → 委派核验 → 规则变化更新结论 → 沙箱执行订单 + 验证实际状态），暴露五类自然失败（压缩丢例外/旧偏好未失效/委派无出处/引用旧状态/"调用成功"但目标未完成）。

**独立描述轴（任务元数据，非难度等级）**：信息规模、信息依赖距离、持久跨度、行动依赖、环境变化。静态长 QA = 诊断题，不冒充 long-horizon。

**第一族实现策略**：以已接线数据为**材料**（HELMET PopQA 语料、LongMemEval-V2 轨迹、MuSiQue 多跳结构）嵌入耦合结构（版本更新事件、延迟约束注入、可验证行动步骤），不从数据集倒推目标，也不重蹈五连败的纯 synthetic 覆辙——每个任务族过任务恒等规则（complete-evidence solvable、非饱和、位置平衡、因果依赖金标）。

### 5.3 三个时间尺度 + 改进效果分解

任务内 / 跨会话跨任务 / 跨改进代际，各自被观察的能力分开记录。效果分解为五类并分别识别：额外计算、反馈条件化生成、更好选择、保留、迁移。对照臂见 5.5。

### 5.4 Reader 证据分级（闭源一等公民）

- **T1 锚**：可钉权重与服务（本地 pinned Qwen3.6-27B@1b559cf…）——机制复现与调试级证据。
- **T2 版本化 API**：指定版本串+时间窗+协议下可承载主要统计结论；资格门 = hy3 实际失败过的那些（前后 canary 答案形态/usage/model-echo，漂移整批作废；≥5 次批内同策略方差地板；超阈拒收）。
- **T3 仅兼容**：无法核算 usage → 只跑兼容性，不入效率比较。
- 任意 API ≠ 只支持 OpenAI-compatible transport：按能力适配消息/工具/流式/计费。多模型调度须固定模型池并核算全部调用（否则"聪明路由"=偷换更强模型）。

### 5.5 对照设计（先 researcher-vs-researcher）

第一阶段的臂：① **固定策略参照**（不更新——判断"更新是否值得"的基准）；② **经验积累-only**（记忆内容增长、策略冻结——分离经验内容 vs 策略更新的贡献，评审的关键问题）；③ **现行 open-S researcher**（CLI 代码编辑）。三者同任务流、同反馈带宽、同资源包。matched 非智能体搜索对照族延后但接口预留（Stateful 公平规则：对照存在则同状态同预算）。

### 5.6 协议语义修正（吸收 v1 review）

- selection-blind 正名为"特定反馈可见性臂"，不再冒充非智能体搜索。
- replay 两用途分开：程序+状态+记账复现（确定性）与重新请求模型（随机性估计）。
- 方差地板改区分：测量不确定性 / 最小实际价值 / 服务漂移 / 系统错误；独立重复可识别小于单次 SD 的均值差。
- C_total(N) = C_improve + N·C_deploy 双成本列。
- 轨迹指标不止终分：获得、保持、迁移、部署代价。
- 状态边界契约 + 泄漏探针保留（v1 §6.3，适配跨会话设定：visible→gate 边界状态重置、金标 canary 注入、状态转录可审计）。
- 工程资格失败 ≠ 科学阴性（v1 review #5 的修正写进 charter）。

## 九、风险与诚实边界

- **规模风险**：v2 是多月工程（生命周期运行时是最大项）；若 B 阶段超期，退化路径 = 砍任务族到 1 个 + 臂到 2 个，先出试点 cell。
- **开放性空转风险**：无外部方法真参评则"开放基准"不成立——投稿前硬性要求 ≥1 个（Recuris Apache-2.0 可适配，或 AutoMem 式架构搜索臂）。
- **近邻挤压**：MemoryArena/Evo-Memory 团队加"改进过程"维度的窗口以月计；差异化钉在耦合生命周期 + 开放方法族 + 成本分离三件事上，任务族设计文档里逐近邻写清"必须额外回答"。
- **声明纪律**：阴性可发表是研究态度不是保证；"RSI 还是搜索"改为识别五类效果的增量贡献；冻结权重是主赛道归因设定，不是 RSI 定义。
